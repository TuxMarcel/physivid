# Technical Requirements and Constraints

## 1. Python Version

The project should be developed using **Python 3**.

## 2. Libraries and Frameworks

### 2.1. Libraries/Frameworks to Use

The following libraries and tools are preferred for this project:

-   **Pymunk:** Essential for implementing the 2D physics simulation.
-   **Pygame (or similar deterministic renderer):** To be used for frame generation in a deterministic and headless manner. It should be capable of rendering graphics off-screen.
-   **FFmpeg:** An external command-line tool crucial for encoding the generated image sequences into video and muxing with the audio track to produce the final MP4 file. The Python script will invoke FFmpeg via shell commands.

### 2.2. Libraries/Frameworks to Avoid

To maintain the CLI-focused, headless, and non-database-centric nature of the project, the following should be explicitly avoided in the initial version:

-   **Web frameworks:** Such as Flask, Django, FastAPI, etc., as the project is not a web application.
-   **GUI frameworks:** Avoid any dependencies that necessitate or create a graphical user interface for application control or rendering. The rendering pipeline must remain headless.
-   **Database-first architecture:** No databases (SQL, NoSQL, etc.) should be used for core data storage in the initial version. If metadata tracking is required later, it can be integrated then.

## 3. Data Handling

### 3.1. Input

All primary inputs to the simulation engine will be provided through command-line arguments. The Python `argparse` module is a suitable candidate for handling these inputs robustly. Expected CLI arguments include:

-   `--seed`: An integer value to initialize the random number generator and thus determine the unique world configuration.
-   `--duration`: A float representing the total video duration in seconds.
-   `--fps`: An integer specifying the frames per second for the video output.
-   `--resolution`: A string (e.g., "1920x1080") defining the width and height of the output video frames.
-   `--output_name`: A string serving as the base name for the final MP4 video file.
-   `--scene_profile`: A string that can be used to select different pre-defined simulation scenarios or world configurations.

### 3.2. Processing

The core processing involves:

-   **Parameter Derivation:** The simulation engine will derive all necessary world parameters (e.g., number of objects, their initial positions, forces, etc.) deterministically from the provided `seed` and `scene_profile`.
-   **Deterministic Simulation:** The physics simulation (via Pymunk) must run deterministically, meaning that for the same seed and inputs, the exact same sequence of physical states will occur.
-   **Frame Generation:** For each time step of the simulation, a corresponding visual frame must be generated by the chosen renderer (e.g., Pygame) off-screen.
-   **Audio Generation:** Synchronously with frame generation, audio data corresponding to in-simulation events (e.g., collisions, object movements) will be generated or arranged.
-   **Stream Preparation:** Both the generated visual frames (as image sequences) and audio data will be prepared for subsequent encoding and muxing by FFmpeg.

### 3.3. Storage

-   **Temporary Files:** During the rendering process, individual frames (e.g., PNG images) and raw audio data (e.g., WAV files) will be stored in a temporary working directory. This directory should be managed to prevent accumulation of large files and ensure cleanup after successful video export.
-   **Final Output:** The finished `.mp4` video files are to be stored in a single, shared, and user-specified output folder (e.g., `output/videos/` relative to the project root, or an absolute path provided by the user).

### 3.4. Output

The primary output of the tool will be:

-   A final rendered MP4 video file, produced by FFmpeg, located in the designated shared output folder.
-   Optionally, the system may generate logs or a metadata JSON file per render, detailing simulation parameters or events. These optional outputs should also be directed to a sensible location, potentially alongside the video or in a dedicated log directory.
